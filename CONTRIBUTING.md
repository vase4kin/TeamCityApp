CI configuration
----------------

Marathon Cloud instrumentation tests are paused by default. To enable them, set
the `ENABLE_MARATHON_TESTS` repository variable to `true` and configure the
`MARATHON_CLOUD_API_TOKEN` repository secret.

Coverage uploads authenticate through GitHub Actions OIDC and do not require a
`CODECOV_TOKEN` repository secret.

Release workflow
----------------

Release Please runs after pushes to `dev` and can be dispatched manually from
that branch. It replaces Release Drafter and maintains a release PR based on
Conventional Commits: `fix` bumps the patch version, `feat` bumps the minor
version, and breaking changes bump the major version. Ordinary `chore` commits
do not trigger a release.

The release PR updates `CHANGELOG.md`, `version.txt`,
`.release-please-manifest.json`, and the marked `versionName` in
`build-logic/src/main/kotlin/Config.kt`. Merge it into `dev` when ready; the next
workflow run creates the `v<version>` tag and GitHub release. Android version
codes are calculated as `major * 10_000 + minor * 100 + patch`, matching the
Bitcoin app's scheme. Major versions must be 1–9999 and minor/patch versions
0–99. The initial `1.52.8` version produces code `15208`, above the previous
code `117`.

The manifest starts at the current app version, `1.52.8`. `bootstrap-sha` marks
the `dev` commit before this workflow was introduced so the initial changelog
does not repeat the repository's historical changes. Release Please ignores
that setting after its first release.

Configure a `RELEASE_PLEASE_TOKEN` repository secret with contents, issues, and
pull-request write access to let CI run automatically on the generated PRs.
The workflow falls back to `GITHUB_TOKEN`; events generated by that token do
not trigger other workflows. For this fallback, enable **Allow GitHub Actions
to create and approve pull requests** in **Settings → Actions → General**.
See the [Release Please token documentation](https://github.com/googleapis/release-please-action#other-actions-on-release-please-prs).

This workflow manages versions and GitHub releases. Building signed artifacts
and uploading to Google Play remain separate steps.
